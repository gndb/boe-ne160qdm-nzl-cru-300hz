# 手动参数与恢复

适用于本仓库 2026-11-05 的核显 300Hz 快照。BIN 来自已保存的 EDID 覆盖；原生参考来自历史缓存，均非重新读取的面板 EEPROM。原生参考未做恢复验证。

## 导入配置

1. 打开 [CRU 官方工具](https://www.monitortests.com/forum/Thread-Custom-Resolution-Utility-CRU)，选择带 `(active)` 的目标内屏，核对面板型号与输出 GPU，用 Export 备份可工作的配置。
2. 下载 [300Hz BIN](BOE0D55-current-300Hz-1298.880MHz.bin)，按 [SHA-256](SHA256SUMS.txt) 核验后 Import。导入会带入多个档位和其他能力描述，检查需要保留的模式。
3. 打开 **DisplayID 2.0 → Detailed resolutions**，核对 300Hz 条目与下表一致。高像素时钟时序应放在 DisplayID 中。
4. 主界面点 OK 保存，运行官方工具包中的 `restart64.exe` 重载驱动。
5. 在 Windows“设置 → 系统 → 屏幕 → 高级显示”选择 300Hz，画面正常后保留更改，再检查活动模式。

`restart required` 表示需要重载驱动。保存和重载完成后，仍需在 Windows 中选择刷新率。

## 手动填写

在 **DisplayID 2.0 → Detailed resolutions** 中添加或编辑对应条目，Timing 选 **Manual**，保留可工作的回退档位。

| 字段 | 水平 Horizontal | 垂直 Vertical |
|---|---:|---:|
| Active | 2560 | 1600 |
| Front porch | 48 | 6 |
| Sync width | 32 | 6 |
| Back porch | 0 | 28 |
| Blanking | 80 | 40 |
| Total | 2640 | 1640 |
| Sync polarity | − | − |

- **Refresh rate：** 300.000Hz。
- **Pixel clock：** 1298.880MHz；水平频率 492.000kHz。
- **Interlaced：** 不勾选。

请按 **H48/32/0、V6/6/28** 填写。总消隐相同而前后沿分配不同，仍属于不同的时序。水平后沿为 0 是这份实验快照的实际值，原厂保证范围尚不明确。

## 恢复

| 情况 | 操作 |
|---|---|
| 在 Windows 切换后异常 | 不保留更改，等待自动回退，再选择原先可用的档位。 |
| 需要撤销目标屏幕的 CRU 覆盖 | 在 CRU 顶部选择该屏幕，点顶部 Delete，保存后重启。 |
| 交互式重启驱动后约 15 秒仍无画面 | 尝试按 F8 临时卸载所有 EDID 覆盖；`/q` 静默运行不提供相同的交互式恢复。 |
| 仍无法恢复 | 在 Windows 安全模式中清理覆盖，完成后重启。`reset-all.exe` 会清除所有显示器的 CRU 覆盖，使用前确认影响范围。 |

CRU 修改注册表中的 EDID 覆盖，不会刷写屏幕固件。详见 [CRU 官方恢复说明](https://www.monitortests.com/forum/Thread-Custom-Resolution-Utility-CRU)。

## 显示检查

确认 Windows 已选中 300Hz，再打开 [TestUFO Frame Skipping Checker](https://www.testufo.com/frameskipping)。待测试帧率稳定在约 **300FPS**、页面显示 `READY`，用相机拍摄 **1/10 秒或更长曝光的静态照片**，重复检查亮块序列是否连续。截图和普通手机慢动作视频不能替代这项检查。

再观察常用负载、连续运行、冷启动与睡眠唤醒，并记录亮度、HDR/VRR 等测试条件。Windows 回读到 300Hz 只说明软件输出模式已接受；一次正常照片也只覆盖当次条件。
