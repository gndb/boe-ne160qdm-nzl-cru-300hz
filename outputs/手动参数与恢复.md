# 手动参数、导入与恢复

## 先保存可工作的配置

在 CRU 中选择自己的活动内屏，使用 Export 导出当前配置。核对设备、面板型号和输出 GPU，保留可用档位及恢复文件。

本仓库的当前 BIN 是 Windows 已保存的 EDID 覆盖快照，不是面板 EEPROM 的重新读取。原生参考 BIN 来自历史缓存，未做恢复验收。完整导入会带入其他能力数据和多个档位。

## 使用当前 BIN

1. 从 README 下载 `BOE0D55-current-300Hz-1298.880MHz.bin`，核对 SHA-256。
2. 打开 CRU，选择带 `(active)` 的目标内屏；`restart required` 是重载提示，不是当前刷新率。
3. Import 导入文件。检查 DisplayID 2.0 内的 300Hz 详细时序与下表相同，确认其他需要保留的模式仍存在。
4. 在主界面点击 OK 保存，再运行官方 CRU 包中的 `restart64.exe` 重载驱动。
5. 驱动恢复后，在 Windows“设置 → 系统 → 屏幕 → 高级显示”中选择 300Hz。

CRU 保存配置和重载驱动不会自动等同于 Windows 已切换至目标刷新率。选中后应回读活动模式，并检查实际显示。

## 手动填写

在 DisplayID 2.0 的详细时序数据块中使用 Manual。先导出旧配置，再编辑对应的 300Hz 条目，保留可工作的回退档位。

| 字段 | 水平 | 垂直 |
|---|---:|---:|
| Active | 2560 | 1600 |
| Front porch | 48 | 6 |
| Sync width | 32 | 6 |
| Back porch | 0 | 28 |
| Blanking | 80 | 40 |
| Total | 2640 | 1640 |
| 极性 | − | − |

Refresh rate 为 300.000Hz，Pixel clock 应为 1298.880MHz，水平频率为 492.000kHz，Interlaced 不勾选。

这是当前实测机器保存的自定义时序，不是标准 CVT-RB2 或 BOE 原厂认证推荐。虽然 CRU 允许零后沿，尚无该面板最小后沿的完整原厂资料。

## 恢复

- 如果只有 Windows 切换模式后异常，不确认“保留更改”，等待系统自动回退；画面恢复后选择已可工作的档位。
- 如果需要撤销覆盖，在 CRU 顶部选择目标屏幕，用顶部 Delete 移除该屏幕的覆盖，保存后重启或重载驱动。它不会刷写屏幕固件。
- 官方交互式 `restart64` 重启后若屏幕超过约 15 秒仍未恢复，可尝试其 F8 恢复模式，临时卸载覆盖；`/q` 静默路径不提供相同的交互式 F8 热键。
- 必要时进入 Windows 安全模式清理目标屏幕覆盖。`reset-all.exe` 会影响所有显示器的覆盖配置，不应当作仅针对本屏幕的恢复按钮。

恢复机制参考 [CRU 官方说明](https://www.monitortests.com/forum/Thread-Custom-Resolution-Utility-CRU)。

## 稳定性检查

先保证 TestUFO 页面约 300FPS 且显示 READY，再拍摄长曝光静态照片。手机慢动作视频会受到采样频率和快门影响，不能单凭视频缺格认定屏幕跳帧。还应重复检查普通桌面、常用负载、冷启动及睡眠唤醒。

读取到 300Hz 是软件输出状态的证据，不等于已经完成零跳帧、色彩、DSC、响应时间或长期稳定性验证。
