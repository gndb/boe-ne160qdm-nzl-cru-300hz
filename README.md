# BOE NE160QDM-NZL：Intel 核显 2560×1600 / 300Hz 配置记录

Experimental CRU/EDID profile for one THUNDEROBOT R16 with Intel UHD Graphics and a BOE NE160QDM-NZL panel. Windows reported 2560×1600 at 300Hz when captured. Physical frame-skipping and long-term stability have not been independently verified.

本仓库保存一台雷神 R16 当前使用的显示覆盖配置及参数说明。**2026-11-05 19:39:38 UTC 采集时，Windows 活动模式回读为 Intel UHD 输出 2560×1600、300Hz。**用户反馈当前方案可用、较前一套方案表现改善。

这是单台机器的实验快照，不是 BOE、Intel 或雷神的认证配置，也不是所有同型号面板的通用最优参数。尚未完成独立的长曝光逐帧验证、长时间负载、冷启动及睡眠唤醒验证。

## 当前实际保存的 300Hz 参数

在 CRU 的 **DisplayID 2.0 → Detailed resolutions** 中选择 **Manual**。

| 参数 | 水平 Horizontal | 垂直 Vertical |
|---|---:|---:|
| Active | 2560 | 1600 |
| Front porch | **48** | **6** |
| Sync width | **32** | **6** |
| Back porch | **0** | **28** |
| Blanking | 80 | 40 |
| Total | **2640** | **1640** |
| Sync polarity | − | − |

- 刷新率：**300.000Hz**，逐行扫描。
- 像素时钟：**1298.880MHz**。
- 水平扫描频率：**492.000kHz**。
- 垂直消隐时间：约 **81.30µs**。

**当前实际水平前沿/同步/后沿为 `48/32/0`。**讨论中曾建议过 `8/32/40`，两者消隐总数相同，但同步位置不同；本仓库保存的是实际读回值，不把建议值当作已使用值。

## 为什么降低像素时钟后可以提供 300Hz

像素时钟由 `水平总计 × 垂直总计 × 刷新率` 决定。有效画面保持 2560×1600，减少的是消隐开销。

| 300Hz 方案 | 总时序 | 像素时钟 | 垂直消隐时间 |
|---|---:|---:|---:|
| 历史原生参考 | 2720×1700 | 1387.200MHz | 约 196.08µs |
| 前一套实验方案 | 2680×1620 | 1302.480MHz | 约 41.15µs |
| **当前保存方案** | **2640×1640** | **1298.880MHz** | **约 81.30µs** |

当前方案比原生参考所需的像素时钟低，同时比前一套实验方案留出更长的垂直消隐。这与用户观察到的改善相符，但多项参数和运行环境可能同时变化，尚未证明单一因果关系。

用户报告约 1304MHz 是本机试验中观察到的可用时钟门槛；这不是已确认的 Intel 精确硬上限。当前 300Hz 活动状态也说明，先前只枚举到 240Hz 不等于核显存在固定的 240Hz 上限。

## 验证配置文件

仓库中的验证器只读取文件，不修改 Windows、注册表或显卡：

```console
python analysis/validate_profile.py
```

它检查校验值、EDID 块完整性、DisplayID 时序与参数表的一致性。它不能验证物理屏幕是否逐帧呈现，也不能代替实机导入测试。

## 显示验证

在 [TestUFO Frame Skipping Checker](https://www.testufo.com/frameskipping) 达到 `READY`、测试帧率稳定后，用相机拍摄曝光 1/10 秒或更长的静态照片，并重复采样。截图和手机慢动作视频不能替代这项检查。再观察常用负载、重启和睡眠唤醒后的表现。

本次整理和导出没有修改当前显示设置、BIOS、面板固件或 TCON。仓库不包含完整注册表、设备实例路径、临时管理员脚本、第三方程序或官方 PDF 的再分发副本。
